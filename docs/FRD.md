# **Functional Requirements Document (FRD)**

**Product Name:** AI Enablement & Consulting Platform

**Document Version:** 1.0

**Technology Stack:** React (TypeScript, React-Router), Node.js, Google Cloud Run, Firestore, Gemini 3.5, Google ADK.

## **1\. System Architecture overview**

The system follows a modern decoupled architecture:

* **Frontend:** A Single Page Application (SPA) built with React and TypeScript, utilizing react-router-dom for client-side navigation.  
* **Backend/API:** A containerized Node.js service, deployed on **Google Cloud Run** for stateless, auto-scaling execution.  
* **AI Orchestration layer:** Google Agent Development Kit (ADK) running within the Node backend, interfacing with the Gemini 3.5 API.  
* **Data Layer:** Firebase/Firestore for user data and session state, utilizing Firestore Vector Search for Retrieval-Augmented Generation (RAG).

## **2\. Frontend Functional Requirements (React/TypeScript)**

### **2.1 Routing & Navigation (react-router)**

* /login: Authentication entry point.  
* /onboarding: Multi-step form for user profiling (Industry, Role, Size).  
* /dashboard: Main layout wrapper containing the consultation interface.  
  * /dashboard/chat: The interactive consultation room with the Multi-Agent System.  
  * /dashboard/canvas: Visual representation of the strategy (Kanban board for use cases, Tech Stack visualizer).  
  * /dashboard/roadmap: Gantt-chart view of the implementation timeline.

### **2.2 UI/UX Behaviors**

* **Type Safety:** All component props, API responses, and state objects must be strictly typed using TypeScript interfaces to prevent runtime errors during rapid development.  
* **Real-time Updates:** The Strategy Canvas must update asynchronously as the user chats with the AI. (e.g., When the Agent suggests a tool, it immediately appears on the Canvas via state management).

## **3\. Backend Functional Requirements (Cloud Run & Node.js)**

### **3.1 Containerization & Deployment**

* The backend API must be Dockerized.  
* Deployed via Google Cloud Run to allow scaling from 0 to N instances based on incoming HTTP traffic.  
* Must securely manage API keys (Gemini, SSO) using Google Cloud Secret Manager integrated with Cloud Run.

### **3.2 Agentic Workflow Implementation (Google ADK)**

The backend must orchestrate the following agents:

* **FR-A1 (Needs Assessment Agent):** Parses frontend chat input, updates the user's current\_state document in Firestore.  
* **FR-A2 (Industry Research Agent):** Triggered when current\_state is complete. Executes a Vector Search query against Firestore to retrieve industry-specific case studies.  
* **FR-A3 (Tech Recommendation Agent):** Takes approved use cases and outputs structured JSON mapping tools to problems.  
* **FR-A4 (Implementation Agent):** Generates roadmap milestones.  
* **FR-A5 (Training Agent):** Generates change management templates.

### **3.3 Data Models (Firestore)**

* **Collection Users:**  
  * uid (String)  
  * profile (Map: industry, role, company\_size)  
* **Collection Sessions:**  
  * session\_id (String)  
  * chat\_history (Array of message objects)  
  * approved\_use\_cases (Array of Strings)  
  * generated\_roadmap (JSON Object)  
* **Collection KnowledgeBase (Vector Enabled):**  
  * document\_id (String)  
  * content (String \- e.g., Case study text)  
  * embedding (Vector/Array of floats generated by Gemini text-embedding models).

## **4\. Non-Functional Requirements**

* **Performance:** Chat responses from the Orchestrator agent should have a TTFB (Time to First Byte) of \< 2 seconds, utilizing streaming responses where possible.  
* **Scalability:** Cloud Run must be configured to handle concurrent agent processing without bottlenecking.  
* **Security:** All API endpoints must be protected by JWT authentication verified against Firebase Auth.
